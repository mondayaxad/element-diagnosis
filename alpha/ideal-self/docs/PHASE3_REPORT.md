## 0. 受入レビュー修正（`7881c56` の続き）

### 修正1：事前に決めた予算と「追い課金しない」を分けた
- 「上限 X 円を超える追い課金をしない」は「X 円までは追い課金してよい」と読めるため、使うのをやめた。
- 文言は `src/commitment_text.js` の関数1か所で作り、作成・引下げ後の約束・「止めて」の返答・振り返りの問いがすべてここの文を使う。
  - 約束：「事前に決めた予算は 1,000 円。足りなくても、期限まで追加で課金しない」
    - 0 円のとき：「事前に決めた予算は 0 円（課金しない）。足りなくても、期限まで追加で課金しない」
  - 止めて：「…事前に予算を 1,000 円と決めて、足りなくても12月5日 12:00まで追加で課金しない、と約束した」
    - 0 円のとき：「12月5日 12:00まで、課金はしない（予算 0 円）。足りなくても追加で課金しない、と約束した」
  - 振り返り：「事前に決めた予算（1,000 円）のほかに、期限まで追加で課金せずに済みましたか」
    - 0 円のとき：「期限まで、課金せずに済みましたか（予算 0 円）」
- 画面の「上限」はすべて「事前に決めた予算」「予算を下げる／上げたい」に直した。作成の画面には、確定前に約束の文を表示する。拒否の文、変更の記録、会話で変更依頼を断る文も合わせた。
- 内部の項目名 `cap_yen` は「事前に決めた予算（円）」の意味で使う（項目名は変えていない）。

### 修正2：ETI 取込同意の撤回で、旧人格版の「止めて」の介入を消す
- 撤回で ETI 由来の人格を消すとき、その版で作った介入（`stopView.intervention`）も取り除く（`dropStaleIntervention`）。
- 消す版を参照している操作の記録（下書き・評価・承認・見直しのログ）も消す。修正の途中で、ログに旧版の識別子が残っているのを E2E で見つけて直した。
- 端末保存から戻すときも、承認済みの版と違う版の介入・会話は使わない（`restoreSaved`。`app.js` から `state.js` に移してテストできるようにした）。
- 本人が入力した約束は残る。人格が無くても見られるように、現在像の選択画面に「約束の記録を見る」を置いた。
- 撤回後に「止めて」を開くと、人格の言葉は出さず、アプリとして行動を伝える。
- 簡易質問経路（ETI 由来でない）の人格の介入は、ETI の撤回で消さない。

### 修正3：削除確認の文言を実際の挙動に合わせた
- 有効な約束を削除するときは、次の3点を確認画面に明記する。
  - 狙う対象・事前に決めた予算・期限・理由・振り返り・この約束の「止めて」の会話の記録をすべて消し、期限などのデータは残さない。
  - 削除した時点でこの約束は有効ではなくなり、期限まで待たずにすぐ新しい約束を作れる。
  - 元に戻せない。
- 「解除ではなく、データの削除です」という、挙動とずれる表現は外した。端末時計の仕様は維持した。

## 1. 流れ

```
ホーム（承認済みの5年後の自分）
  → 約束をつくる（1/2）：狙う対象・手持ちの石・必要と思う石・追加で必要と見積もった金額（模擬）・理由
  → 約束をつくる（2/2）：「その金額を出せるか」「出す価値があるか」→ 上限（円）と期限（3/7/14/30日）を確定
  → 有効な約束：上限の引下げのみ（引上げ・解除は期限まで不可）
  → 「止めて」：有効な約束 → 5年後の自分の言葉と、その場でできる行動を一つ
  → 期限 → 振り返り（守れた／一部／守れなかった／不明 ＋ 何が助けになったか）
  → 記録の閲覧・削除（約束中でも可）
```

## 2. 依頼ごとの実装

### 2-1 約束を作る（`src/commitment.js`）
- 狙う対象・手持ちの石・必要と思う石・追加で必要と見積もった金額・理由を入力する。
  - 金額は「あなたの見積もり・模擬」と表示し、`estimate_source: self_mock_input` として記録する。
  - 足りない石は差だけを計算する。金額への換算はしない（自動見積もりなし）。
- 「その金額を出せるか」「出す価値があるか」の両方に答えるまで、上限の欄と確定のボタンは使えない。
  - 「いいえ」「わからない」があれば上限 0 円を勧め、欄に0を入れておく。両方「はい」なら見積もり額を示す。決めるのは本人。
- 確定すると、約束の文「期限まで、上限 X 円を超える追い課金をしない」と期限（作成時刻＋日数）を固定する。
- 有効な約束がある間は、新しい約束を作れない（作り直しで上限を上げる抜け道をふさぐ）。

### 2-2 約束を守る
- 期限前は上限の引下げだけを受け付ける。引上げ（`raise_forbidden`）・解除（`cancel_forbidden`）・同額や上げる値での「引下げ」（`not_lower`）は拒否する。期限は変えられない。
- 期限ちょうどで自動的に終わる（`statusAt`）。終わった約束は、引下げも含めて変更できない（`ended`）。終わった後は振り返りだけ記録できる。
- 更新は版（`version`）付きで行う。同じ画面からの2回目、別の画面に残った古い版からの操作は `stale_version` として拒否し、1回分だけ反映する。二重の確定も拒否する（`no_draft`）。
- **会話と約束の更新処理の分離**
  - `dialogue.js`（会話）と `intervention.js`（止めて）は、約束のモジュールも状態のモジュールも読み込まない。
  - `sendMessage` の実装は、約束の更新関数を呼ばない。この3点をテストでソースから確かめている。
  - 会話で「上限を上げて」「解除して」「期限を延ばして」「追い課金していい？」、JSON の形の入力などを送ると、`commitment_change_blocked` として断る。約束の画面では引下げだけができると案内する。

### 2-3 「止めて」からの介入（`src/intervention.js`）
- ホーム・約束の画面・会話の画面に「止めて」のボタンを置いた。会話で「止めて」と入れても同じ介入になる（約束は読むだけ）。
- 画面の並びは次の順（E2E で確認）。
  1. 有効な約束（約束の文・対象・上限・期限と残り時間・決めた理由）
  2. 承認済みの5年後の自分（固定の仮アバター・版）
  3. 本人の決めた理由を踏まえた言葉
  4. その場でできる行動を一つだけ
- 行動は、承認済みの版の「困ったときの振る舞い」（E4）から一つ選ぶ。どれも購入画面を閉じることから始まる。例：「いま開いている購入画面を閉じて、5分だけ一人で考える時間をとろう」。
- 「このアプリは、ほかのアプリやお店での購入を止めることはできません。画面を閉じるのは、あなたの手です。」と必ず添える。「停止しました」「止めました」などの表示が無いことをテストで確かめている。
- 承認済みの人格が無いときは、人格のふりをせず、アプリとして行動を伝える。
- 強い苦痛の表現は、Phase 2 の中断処理を引き継ぐ。
  - 会話が中断されている間に「止めて」を押した場合、約束の表示と案内は出すが、人格の言葉は出さない。
  - チャットで「止めて」と入れても中断のままになる。

### 2-4 振り返る
- 期限の後に、「追い課金せずに済んだか」を本人が「守れた／一部守れた／守れなかった／不明」から選ぶ。何が助けになったか（7項目から複数選択・「特になし」は単独）と任意のメモ（200字まで）も記録できる。
- 集計は「有効・守れた・一部・守れなかった・不明・未記録」に分ける。未記録は「守れなかった」に数えない。
- 記録の一覧・詳細で閲覧できる。削除は1件ずつと「すべて削除」の2通りで、どちらも確認の一手間がある。約束中でも削除できる。
  - 削除すると、約束・振り返りに加えて、その約束に触れた「止めて」の会話の記録と、操作の記録（ログ）も消す。約束に関係しない会話は残す。

## 5. 判断したこと・未確認事項

1. **削除と約束の固さ**：受入レビューで「有効な約束も削除可能・期限などのデータは残さない」と決まった。削除後はすぐに新しい約束を作れることを、確認画面に明記した（§0 修正3）。
2. **期限の後に上限を超えていたかは、アプリは知らない**：振り返りは本人の申告だけで、外部の購入の記録とはつながない。
3. **時刻は端末の時計**：今回のαでは維持する（受入レビューで決定）。端末の時計を進めれば期限を早められる。
4. **行動の候補は5種類のルール**（E4 から選ぶ）。本人の評価や振り返りの結果で選び方を変えることはしていない。
5. 約束・振り返りは、記憶の保存に同意したときだけ端末に残る（同意しなければ、画面を閉じると消える）。サーバーには送らない。
6. 入力中に理由を選ぶと入力した値が消える不具合と、拒否の理由が「invalid_cap」のような内部の名前のまま表示される問題を、E2E で見つけて直した。
