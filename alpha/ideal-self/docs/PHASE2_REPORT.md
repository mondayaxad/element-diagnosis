## 0. 受入レビュー修正（`86535b5` の続き・対話 `ISA-DIALOGUE-0.2.0`）

### 修正1：見直しで追加質問が複数出たとき、2問目を飛ばしていた
- 原因：見直しの並びに「未回答の追加質問」だけを入れていたため、1問目に答えるとその質問が並びから消え、位置がずれて「見直しはここまで」（ボタン無効）になっていた。
- 修正：並びに「未回答のもの」と「この見直しの中で答えたもの」の両方を入れる（出なくなった追加質問は自然に外れる）。答えた後は、その後ろの最初の未回答へ進む（無ければ前に残った未回答、どちらも無ければ終わり）。`revisionComplete()` が真になるまで「見直した人物に会う」は無効で、`finishRevision()` も拒否する。画面に「未回答 n 問」を表示する。
- 再現経路（K1 で内省と慎重さ → 見直しで E1 を「場を明るくする力」）で、状態遷移テストとスマホE2Eの両方で確認した。2問目から戻って1問目を答え直した場合と、E1 を戻して確認が不要になった場合も確認した。

### 修正2：見直しのキャンセル
- 見直しを始めるときに、開始前の状態を保存する。保存するのは、回答・追加質問・表示していた下書き・評価・候補の確認・版の履歴・元の画面。
- キャンセル（「見直しをやめて元に戻す」または最初の質問からの「戻る」）で、保存した状態に戻す。
- 承認済みの固定内容・承認の記録・会話は保存の対象に含めず、触れない。見直し中もキャンセル後も、会話は承認済みの同じ版を使い、会話の記録もそのまま残る。

### 修正3：模擬対話の相談窓口の案内
- 未確認の電話番号・受付時間を外した。画面で使うファイルに電話番号の形・「24時間」・窓口の固有名が無いことをテストで確認している。
- 強い苦痛の表現があると、人格としての返答をせず、通常の模擬対話を中断する（`dialogue.halted`。続きを送ろうとしても拒否）。
- 案内の文面は、身近な信頼できる人と、お住まいの地域の公的な相談窓口につながるよう促すもの。命の危険があるときは緊急通報を促す。番号は書かない。
- 続けるときは、本人が「新しく話し始める」を押す（記録は空から始まる）。固定内容は変わらない。

## 1. スマホでの操作の流れ

```
説明・同意 → 現在像（合成ETI／簡易6問）→ 理想像の質問 → 人格の下書き
  → 初対面（固定の仮アバター・台詞・残す自分らしさ／育てたい力／憧れる魅力・候補の確認）
  → 3軸評価（各1〜5）
      ├ 1・2 の軸あり → 理由を選ぶ → 該当する質問だけ見直す → 新しい版で初対面に戻る
      └ すべて 3 以上 → この版を承認 → 版を固定 → ホーム
  → 短い模擬対話（承認した版だけを使う・最大6往復）
```

## 2. 依頼ごとの実装

### 2-1 初対面（固定の仮アバター）
- アバターは固定の SVG（`assets/avatar-placeholder.svg`、ID `placeholder-night-v1`）。人格・尺度から外見を作らず、性別・顔立ち・年齢などは推測しない。ファイルの内容の値（FNV-1a）を `AVATAR.content_fnv1a` に持ち、ファイルが変わるとテストと固定内容の検証が失敗する。
- 画面には FutureSelfProfile から「残す自分らしさ」「育てたい力」（能力＋具体的な振る舞い）「憧れる魅力」（統合のしかた）と、初対面の台詞を表示する。
- 台詞はルールで組み立てる（`buildGreeting`）。確定した保護特性・成長目標・憧れ・印象の意図（E3）だけを使い、候補は使わない。根拠の要素を記録し、「あなたの回答から組み立てた台詞です。予測ではありません」と添える。

### 2-2 K1 の直接選択と、K2・K4 からの推論候補を分離
- `protected_traits`（保護特性）に入るのは次の2つだけ。
  - K1・F_KEEP で直接選んだもの（`basis: direct_choice`）
  - 初対面で本人が「残したい」を選んだ候補（`basis: confirmed_at_first_meeting`。元の根拠は `basis_before` に残る）
- `protected_trait_candidates`（候補・`system_inferred`）には次の3種類が入る。
  - K2・K4 の回答から読み取ったもの（`inferred_from_answer`。根拠の回答は `mapping: interpreted`）
  - 現在像から導いたもの（`derived_from_current`）
  - 本人が「ふだんは逆」と答えて確認待ちに戻したもの（`demoted_by_answer`）
- 初対面画面で、候補ごとに「残したい／残さない／まだ決めない」を選べる。選ぶたびに新しい版になる。「まだ決めない」に戻すと元の版と同一に戻る（決定的）。
- 要約・台詞・継続の判断原則（DP_CONTINUITY）・`expression_profile.preserve` は、確定した保護特性だけを使う。
  - 反転を避ける制約と振る舞いの土台には、「残さない」と答えたもの以外の候補も使う（`preserve_candidates`）。確かめる前に性格を反転させないためである。
- 追加質問（inversion）の文面も分けた。K2・K4 だけの場合は「回答から『…』を大切にしているように読み取れます」と表示し、本人の選択とは言わない。

### 2-3 3軸評価と、該当部分だけの見直し
- 「自分らしさ・憧れ・到達可能性」を各1〜5の整数で評価する。評価は、表示している版（`persona_version`）にだけ記録できる。
- 1・2 の軸があるときは、その軸の理由を選ぶ（7種類。`REVIEW_REASONS`）。理由に対応する選択式の質問だけを見直す。
  - 例：「憧れる魅力が違う」→ E1 だけ
  - 例：「残す自分らしさが違う」→ K1・K4
- 見直しで回答が変わって新たに必要になった追加質問は、見直しの中で出す。ほかの回答は変わらない（テストで確認）。
- 1・2 の軸がある間は承認できない（α での判断。§5 参照）。すべて3以上でも「違和感があるので見直す」から任意に見直せる。
- 版の履歴（`persona.versions`）に、未確認・修正待ち・承認済み・置き換え済みの状態を残す。

### 2-4 承認・固定と、模擬対話
- 承認の条件は次の3つ。
  - 表示している版である
  - その版の最新の評価がある
  - 評価に 1・2 の軸がない
- 承認すると、人格・判断原則・アバター・台詞・承認時の評価をひとまとめに固定する（`persona.locked`）。
  - 中身はすべて凍結（`Object.freeze`）し、内容のハッシュ（`content_hash`）で改変を検出する。
  - 端末保存から戻すときは検証し直し、改変されていれば使わない。
- 模擬対話はルールで返答する（LLM なし・外部送信なし・最大6往復）。固定した版だけを読み、返答に根拠の要素（判断原則の ID など）を添える。
- 書き換えの依頼は断る（`rewrite_blocked`）。対象は「性格を変えて」「原則を変えて」「設定を忘れて」などと、JSON・項目名で人格を送り込む入力。
- 会話の処理は会話の記録を足すだけで、固定内容・回答・下書き・同意には触れない。
- 見直しで新しい版を作っている間も、会話は承認済みの版のまま。新しい版を承認すると切り替わり、古い版は「置き換え済み」になる。
- 強い苦痛の表現には人格の話をせず、身近な人や相談窓口を案内する。
- ETI の同意を撤回すると、ETI 由来の固定した人格・版・評価・会話も消す。簡易質問経路の固定は残す。

## 5. 判断したこと・未確認事項

1. **ホーム画面のモックアップ**：「先ほどのホーム画面モックアップ」は、このセッションにもリポジトリにも見当たらなかった。Phase 1 の夜の配色で組んである。画像を共有いただければ合わせる。
2. **1・2 の軸がある間は承認できない**ようにした（違和感を残したまま固定しないため）。本人が低評価のまま承認したい場合を認めるかは判断をお願いしたい。
3. **台詞と模擬対話の文面**は、ルールで組み立てた暫定のもの。口調は E3（相手に残したい印象）の4種類で語尾を変えるだけで、プリセットは選ばせていない。
4. **相談窓口の案内**：受入レビュー修正で、未確認の番号・受付時間を外した（§0 修正3）。具体的な窓口を載せる場合は、運営者側で確認した情報だけを載せる。模擬対話は医療・危機対応を目的としていない。
5. **固定の強さ**：固定は端末内の凍結とハッシュによる検出であり、端末の持ち主が保存データを書き換えることまでは防げない。その場合は検出して使わない。サーバー側での固定は、実データ・アカウント接続の判断と合わせて検討が必要。
6. 評価の値は保存しているが、集計・分析には使っていない（外部送信もしない）。
7. 承認後に Phase 1 の回答へ戻って変えた場合も、新しい下書きの版になるだけで、固定した版は変わらない（新しい版を承認するまで会話は旧版）。
