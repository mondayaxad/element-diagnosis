# iPhone での本人テスト：試用環境と起動手順（Phase 4 準備）

基準：受入済みの `f216543`。この手順は `c8d4463` で追加し、練習の約束などを足した版で更新した。合成データのまま、本人の iPhone だけで開ける方法です。公開・実データ接続・実決済は含みません。

## 0. しくみ（何がどこにあるか）

```
Mac（本人）                                   iPhone（本人）
  node scripts/serve.js … 画面のファイルを配信    Safari … 画面を開いて操作
  （受け取るデータは無い）           ──────▶   回答・人格・約束・振り返りは
                                                 iPhone の Safari の中にだけ保存
```

- サーバーは画面のファイル（HTML・JS・CSS・仮アバター）を配るだけです。アプリは外部と通信しません（CSP で禁止。Phase 1〜3 のテストで確認済み）。回答や約束は Mac にも届きません。
- 「本人限定」は2段で守ります。
  1. その端末だけが届く経路（Tailscale の tailnet 内、または自宅の Wi-Fi 内）
  2. 起動のたびに作るアクセスキー（キー付きの URL を開いた端末だけに Cookie を置き、それ以外には何も配信しない＝403）

## 1. おすすめ：Tailscale（tailnet 内だけの HTTPS）

自宅の外でも7日間使え、URL（＝iPhone 側の保存先）が変わりません。

### 準備（最初の1回）
1. Mac と iPhone に Tailscale を入れ、**同じアカウント**でログインする（iPhone は App Store の「Tailscale」）。
2. Tailscale の管理画面で **MagicDNS** と **HTTPS 証明書** を有効にする（`tailscale serve` を初めて使うときに案内が出ます）。
3. tailnet に本人以外の端末・利用者がいないことを確認する（いる場合も、アクセスキーで開けません）。

### 起動（Mac）
```bash
cd element-diagnosis
git fetch origin claude/ideal-self-agent-phase1-91er9p
git checkout <この手順を含むコミット>
# 127.0.0.1 のまま、アクセスキー必須で起動（Mac がスリープしないよう caffeinate を付ける）
caffeinate -i node alpha/ideal-self/scripts/serve.js 4173 --key
#   → 「http://127.0.0.1:4173/?k=<キー>」と表示される。<キー> を控える

# 別のターミナルで、tailnet 内だけに HTTPS で出す（funnel は使わない）
tailscale serve --bg 4173
tailscale serve status        # 「(tailnet only)」と、https://<Mac名>.<tailnet名>.ts.net が出ることを確認
```
- App Store 版の Tailscale では、コマンドは `/Applications/Tailscale.app/Contents/MacOS/Tailscale` です（`tailscale` の代わりに使う）。
- **`tailscale funnel` は使わないでください**（インターネットに公開されます）。

### iPhone で開く
1. iPhone の Tailscale を ON にする。
2. Safari で `https://<Mac名>.<tailnet名>.ts.net/?k=<キー>` を開く。キーは自動で URL から消え、以後はこの Safari では `https://<Mac名>.<tailnet名>.ts.net/` だけで開けます。
3. 最初の画面で **「記憶の保存」に同意**する。7日間のテストでは必須です。同意しないと、タブを閉じると消えます。
4. ETI 経路を試すなら「ETI結果の転用」にも同意する（合成データです）。

### 終わるとき
```bash
tailscale serve reset   # tailnet への出し方を消す
# serve.js は Ctrl+C で止める
```

## 2. 代わりの方法：自宅の Wi-Fi 内（アクセスキー必須）

Tailscale を入れない場合の方法です。Mac と iPhone が同じ Wi-Fi のときだけ使えます。
```bash
caffeinate -i node alpha/ideal-self/scripts/serve.js 4173 --lan
#   → 「iPhone で開く URL: http://192.168.x.x:4173/?k=<キー>」と表示される
```
- iPhone の Safari でその URL を開きます。キー無しでは何も配信しません（403）。
- 注意点
  - 通信は暗号化されません（HTTP）。家族共用以外の Wi-Fi（カフェ・職場など）では使わないでください。
  - Mac の IP アドレスが変わると URL が変わり、iPhone 側の保存（回答・約束）が別扱いになって見えなくなります。7日間のテストでは、ルーターで Mac の IP を固定するか、Tailscale をおすすめします。
  - Mac でサーバーを起動し直すとキーが変わります。新しく表示された URL を iPhone で開き直してください（保存されたデータはそのまま残ります）。

## 4. iPhone の Safari での注意

| 項目 | 内容 |
|---|---|
| 開き方 | **通常の Safari タブ**で開く。プライベートブラウズでは保存されない。**ホーム画面に追加しない**（Safari と保存先が分かれ、記録が見えなくなる） |
| 保存の期限 | Safari は、しばらく開かれないサイトのデータを消すことがある（目安7日）。毎日開く必要はない。途中で記録が消えていないか心配なら、§6 の手順でいつでも確かめられる。Day 7 の前に念のため記録の画面をスクリーンショットで残しておくと安心 |
| 時刻 | 約束の期限は iPhone の時計で判定する（端末時計の仕様は今回のαで維持） |
| 消すとき | アプリの「記録の削除」、または iPhone の 設定 › Safari › 詳細 › Webサイトデータ で該当のサイトを削除 |
| 動作確認の範囲 | ここで確認したのは Chromium のスマホ幅（390×844）での E2E と、キー付き配信の動作。**実機の iPhone Safari（WebKit）では未確認**のため、最初の通しで表示・操作を確かめる |

## 5. 初回の通し（練習の約束・1分）

架空のガチャ場面で、「約束を作る → 止めて → 期限到達 → 振り返り」を一度に試します。練習の約束は期限が1分で、通常の約束・7日間の集計には入りません。画面には「練習」と表示されます。

| 順 | 画面での操作 | 確かめること |
|---|---|---|
| 1 | 同意（**記憶の保存**にチェック）→ 現在像 → 理想像の質問 → 下書き →「5年後の自分に会う」→ 3軸評価 → 承認 | 初対面：自分らしいか・憧れるか・5年後ならあり得るか（1〜5と、違和感の理由） |
| 2 | ホームの「**練習（1分）で試す**」→ 狙う対象（架空）・手持ちの石・必要と思う石・見積もった金額・理由 →「出せるか」「価値があるか」→ 事前の予算 →「この練習の約束で決める」 | 欲しいもの・必要額・出す価値を整理し、納得して予算を決められるか。上部に「練習です」と出ているか |
| 3 | 「あと3,000円で届きそう」と思った場面を想定して、ホームの「**止めて**」を押す | 約束が最初に見えるか。5年後の自分の言葉（先頭に「（練習）」）と、その場でできる行動が一つ示されるか |
| 4 | 同じ画面の「**実際に取った行動（任意）**」で、実際にしたことを選んで記録する（しなくてもよい） | 提案とは別に、自分の行動を選べるか |
| 5 | 1分待つ → ホームの「約束の記録」→ 練習の記録 →「振り返る」→ 守れた／一部／守れなかった／不明 → 助けになったこと → 記録する | 選んだ行動と、何が助けになったかを記録できるか。集計が「0」のまま（練習は入らない）か |
| 6 | 練習の記録は、詳細画面の「この記録を削除…」で消してよい | — |

通しのあと、7日間のテストでは、ホームの「**約束をつくる**」（練習ではない方）から期限「7日」を選びます。

## 6. 再起動の後に記録が残っているかの確認

記録は iPhone の Safari の中にあるので、Mac やサーバーを再起動しても消えません。ただし、アクセスキーは起動のたびに変わります。

| 起きたこと | すること | 確かめること |
|---|---|---|
| Mac のサーバー（serve.js）を起動し直した | 新しく表示された `?k=<キー>` 付きの URL を、iPhone の Safari で開き直す。Tailscale なら `https://<Mac名>.<tailnet名>.ts.net/?k=<新しいキー>` | ホームに承認済みの5年後の自分と、有効な約束（予算・期限）が出るか |
| Mac 自体を再起動した | serve.js と `tailscale serve --bg 4173` をもう一度実行し、上と同じく新しい URL を開く | 同上 |
| iPhone の Safari を閉じた・iPhone を再起動した | 同じ URL（キーなし）を Safari で開く | 同上。「約束の記録」の件数・振り返りが前と同じか |
| 画面に「forbidden」とだけ出た | キーが変わったか、Cookie が消えた。Mac に表示されている最新のキー付き URL を開く | 開いた後に記録が残っているか |
| 記録が見えない | URL（ホスト名・IP・ポート）が前と同じか確かめる。違うと保存先が別になる。プライベートブラウズ・ホーム画面のアイコンから開いていないか確かめる | — |

## 7. Day 7 にメモすること

7日間のテストの終わりに、次のことを書き留めてください（アプリには書き出し機能がありません。画面のスクリーンショットと手書き・メモアプリで残してください）。

1. **約束**：狙った対象、事前に決めた予算、期限、決めた理由。途中で予算を下げたか。
2. **「止めて」**：開いた回数と、そのときの場面（「あと少しで届きそう」だったか）。開かなかった場合はそのことも。
3. **取った行動**：「止めて」の後に実際にしたこと（アプリに記録したもの・しなかったもの）。提案された行動と同じだったか。
4. **結果**：期限まで追加で課金せずに済んだか（守れた／一部／守れなかった／不明）。アプリの振り返りに記録したか。
5. **助けになったこと**：5年後の自分の言葉・約束の画面・購入画面を閉じたこと など。助けにならなかったこと。
6. **5年後の自分の印象**：初対面の3軸（自分らしさ・憧れ・到達可能性）が、7日たって変わったか。違和感が出た言葉。
7. **困ったこと**：表示の崩れ、操作しにくい所、記録が消えた・見えなくなった、キーや URL で開けなかった など（日時と画面も）。
8. **スクリーンショット**：ホーム、約束の記録（集計）、約束の詳細（変更の記録・取った行動・振り返り）。

## 9. この版で決めたこと

- 練習の約束（1分）を追加した。通常の約束の「有効な約束は1つ」・期限（3／7／14／30日）・変更ルール・7日間の集計には影響しない。練習の約束も、変更のルールは同じ（予算は下げることだけできる）。
- 「止めて」の後に、実際に取った行動を任意で記録できるようにした。提案された行動・約束の結果（振り返り）とは別に記録し、記録しなかった場合に行動や結果を推定しない。
- 記録の書き出し機能は追加しない（Day 7 のメモはスクリーンショットと手書きで残す）。
- 毎日開くことは必須にしない。
