# iPhone での本人テスト：試用環境と起動手順（Phase 4 準備）

基準：受入済みの `f216543`（この手順の追加はその続き）。合成データのまま、本人の iPhone だけで開ける方法です。公開・実データ接続・実決済は含みません。

## 0. しくみ（何がどこにあるか）

```
Mac（本人）                                   iPhone（本人）
  node scripts/serve.js … 画面のファイルを配信    Safari … 画面を開いて操作
  （受け取るデータは無い）           ──────▶   回答・人格・約束・振り返りは
                                                 iPhone の Safari の中にだけ保存
```

- サーバーは画面のファイル（HTML・JS・CSS・仮アバター）を配るだけです。アプリは外部と通信しません（CSP で禁止。Phase 1〜3 のテストで確認済み）。回答や約束は Mac にも届きません。
- 「本人限定」は2段で守ります。
  1. その端末だけが届く経路（Tailscale の tailnet 内、または自宅の Wi-Fi 内）
  2. 起動のたびに作るアクセスキー（キー付きの URL を開いた端末だけに Cookie を置き、それ以外には何も配信しない＝403）

## 1. おすすめ：Tailscale（tailnet 内だけの HTTPS）

自宅の外でも7日間使え、URL（＝iPhone 側の保存先）が変わりません。

### 準備（最初の1回）
1. Mac と iPhone に Tailscale を入れ、**同じアカウント**でログインする（iPhone は App Store の「Tailscale」）。
2. Tailscale の管理画面で **MagicDNS** と **HTTPS 証明書** を有効にする（`tailscale serve` を初めて使うときに案内が出ます）。
3. tailnet に本人以外の端末・利用者がいないことを確認する（いる場合も、アクセスキーで開けません）。

### 起動（Mac）
```bash
cd element-diagnosis
git fetch origin claude/ideal-self-agent-phase1-91er9p
git checkout <この手順を含むコミット>
# 127.0.0.1 のまま、アクセスキー必須で起動（Mac がスリープしないよう caffeinate を付ける）
caffeinate -i node alpha/ideal-self/scripts/serve.js 4173 --key
#   → 「http://127.0.0.1:4173/?k=<キー>」と表示される。<キー> を控える

# 別のターミナルで、tailnet 内だけに HTTPS で出す（funnel は使わない）
tailscale serve --bg 4173
tailscale serve status        # 「(tailnet only)」と、https://<Mac名>.<tailnet名>.ts.net が出ることを確認
```
- App Store 版の Tailscale では、コマンドは `/Applications/Tailscale.app/Contents/MacOS/Tailscale` です（`tailscale` の代わりに使う）。
- **`tailscale funnel` は使わないでください**（インターネットに公開されます）。

### iPhone で開く
1. iPhone の Tailscale を ON にする。
2. Safari で `https://<Mac名>.<tailnet名>.ts.net/?k=<キー>` を開く。キーは自動で URL から消え、以後はこの Safari では `https://<Mac名>.<tailnet名>.ts.net/` だけで開けます。
3. 最初の画面で **「記憶の保存」に同意**する。7日間のテストでは必須です。同意しないと、タブを閉じると消えます。
4. ETI 経路を試すなら「ETI結果の転用」にも同意する（合成データです）。

### 終わるとき
```bash
tailscale serve reset   # tailnet への出し方を消す
# serve.js は Ctrl+C で止める
```

## 2. 代わりの方法：自宅の Wi-Fi 内（アクセスキー必須）

Tailscale を入れない場合の方法です。Mac と iPhone が同じ Wi-Fi のときだけ使えます。
```bash
caffeinate -i node alpha/ideal-self/scripts/serve.js 4173 --lan
#   → 「iPhone で開く URL: http://192.168.x.x:4173/?k=<キー>」と表示される
```
- iPhone の Safari でその URL を開きます。キー無しでは何も配信しません（403）。
- 注意点
  - 通信は暗号化されません（HTTP）。家族共用以外の Wi-Fi（カフェ・職場など）では使わないでください。
  - Mac の IP アドレスが変わると URL が変わり、iPhone 側の保存（回答・約束）が別扱いになって見えなくなります。7日間のテストでは、ルーターで Mac の IP を固定するか、Tailscale をおすすめします。
  - Mac でサーバーを起動し直すとキーが変わります。新しく表示された URL を iPhone で開き直してください（保存されたデータはそのまま残ります）。

## 4. iPhone の Safari での注意

| 項目 | 内容 |
|---|---|
| 開き方 | **通常の Safari タブ**で開く。プライベートブラウズでは保存されない。**ホーム画面に追加しない**（Safari と保存先が分かれ、記録が見えなくなる） |
| 保存の期限 | Safari は、しばらく開かれないサイトのデータを消すことがある（目安7日）。テスト中は毎日1回は開く |
| 時刻 | 約束の期限は iPhone の時計で判定する（端末時計の仕様は今回のαで維持） |
| 消すとき | アプリの「記録の削除」、または iPhone の 設定 › Safari › 詳細 › Webサイトデータ で該当のサイトを削除 |
| 動作確認の範囲 | ここで確認したのは Chromium のスマホ幅（390×844）での E2E と、キー付き配信の動作。**実機の iPhone Safari（WebKit）では未確認**のため、最初の通しで表示・操作を確かめる |

## 5. 最初の通し（架空のガチャ場面）の進め方

| 場面 | 画面での操作 | 確かめること（Phase 4 の表） |
|---|---|---|
| 初対面 | 同意（記憶の保存）→ 現在像 → 理想像の質問 → 下書き →「5年後の自分に会う」→ 3軸評価 → 承認 | 自分らしいか・憧れるか・5年後ならあり得るか（評価の 1〜5 と、違和感の理由） |
| 約束を作る | ホーム →「約束をつくる」→ 狙う対象・手持ちの石・必要と思う石・見積もった金額（架空）・理由 →「出せるか」「価値があるか」→ 事前の予算と期限 | 欲しいもの・必要額・出す価値を整理し、納得して予算を決められるか |
| 模擬の衝動 | 「あと3,000円で届きそう」と思った場面を想定し、ホームの「止めて」を押す | 約束が最初に見え、5年後の自分の言葉から、その場で取る行動を選べるか |
| 振り返り | 期限の後に「振り返る」→ 守れた／一部／守れなかった／不明 → 助けになったこと | 選んだ行動と、何が助けになったかを記録できるか |

## 6. 本人テストの前に決めておきたいこと（現状の仕様との差）

1. **通しの1回で振り返りまで進めない**：期限は 3／7／14／30 日の選択だけで、振り返りは期限の後にしか記録できない。通しで振り返りまで確かめるには、練習用の短い期限（例：10分）を設けるか、通しでは振り返りを省いて7日間のテストで確かめるかを決める必要がある。
2. **「選んだ行動」を記録する欄が無い**：「止めて」は行動を一つ示すだけで、本人がどの行動を取ったかを記録する欄は無い。振り返りの「助けになったこと」（購入画面を閉じた・時間を置いた など）で間接的に残る。行動そのものを記録する欄を足すかどうかを決める必要がある。
3. **記録の持ち出し**：記録は iPhone の中だけにあり、書き出す機能は無い。本人テストの結果をレビューに使う場合は、画面のスクリーンショットで残すか、書き出し機能を足すかを決める必要がある。
