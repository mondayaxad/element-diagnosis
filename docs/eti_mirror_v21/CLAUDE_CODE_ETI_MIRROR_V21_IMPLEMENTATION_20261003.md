## 4. 通常スコア式：添付正本を厳密に維持

20軸：

- PERSONALITY：O / C / E / A / N
- STYLE：AGY / REL / ROL / REF / AUT
- VALUES：SD / ST / HE / AC / PO / SE / CO / TR / BE / UN

PERSONALITY / STYLEは `1 - sqrt(mean(((user - character)/100)^2))`。
VALUESはユーザーとキャラをそれぞれ領域内平均で中心化し、cosineを `(1 + cosine)/2`へ変換。いずれかがゼロベクトルなら0.5。

`mirrorScoreRaw = 100 * (0.40*pSim + 0.30*sSim + 0.30*vSim)`。
表示用整数は従来どおり `Math.round(mirrorScoreRaw)`。

VALUESまで絶対RMSEに置き換えない。旧Big5/エニアグラム/カテゴリ一致を通常スコアへ加算しない。実行時頻度ボーナス、抽選、利用者ごとの出現数調整、スコアの引き伸ばしも使わない。均等化は確定座標に織り込み済み。

## 5. 1人のMIRRORを選ぶ規則

1. 全118名の丸め前の通常スコアを計算する。
2. 最大スコアをアンカーに、差が `1e-10` percentage points以内の候補だけを同率集合とする。0〜1スコアでは`1e-12`。これは数値誤差吸収で、1ptや整数表示を同率扱いするための幅ではない。
3. 候補が1人ならそのキャラを選ぶ。
4. 複数なら元素一致で絞る。一致する候補が0人なら候補集合を維持する。
5. まだ複数なら国家一致、次に武器一致で同様に絞る。
6. なお複数なら確定データ配列のcanonicalIndexが最小のキャラを選ぶ。

従来の同率時pSim→sSim→vSimによる優先は、1人のMIRROR選択では使わない。生スコアランキングの既存契約は維持してよい。

属性の判定は既存ETI-TRANS-2.0.0の正本プロトタイプで行う。日本語UIに表示されたラベルや旧版の結果から推測しない。診断属性側の距離が同率（最小距離から1e-12以内）なら全同率属性を一致対象とする。国家が平坦なら全8国家が同率。DBのregionが8国家のどれにも属さない場合は国家一致なし。武器のUI別名などを新しく推測して補正しない。

εを組み込んだペア比較sortは、近さが連鎖して非推移的になり得る。必ず最大値アンカーから候補集合を作り、その中だけ属性優先を適用する。配列のランダムシャッフルは禁止。

## 6. 実装方針：スコアランキングと選択MIRRORを分離

既存`computeMirrorV2()`が配列を返す場合は、その関数契約を維持することを第一案とする。別の選択ヘルパーで `{mirror, rankings, selectionMeta}` を返す。既存呼出元を調べ、必要なら実リポジトリのAPIに合わせて同等の構造を導入する。

参照呼出例：

```js
const rankings = ETIv2.computeMirrorV2(results, ETI_V2_CHARACTERS, ETI_V2_META);
const selection = ETIMirrorSelectionV21.selectMirrorV21(results, rankings, {
  engine: ETIv2,
  meta: ETI_V2_META,
  elementPrototypes: ELEMENT_PROTOTYPES_V2,
  nationPrototypes: NATION_PROTOTYPES_V2,
  weaponPrototypes: WEAPON_PROTOTYPES_V2,
});
const mirror = selection.mirror;
```

参照JSは正本の名前・rankフィールドを前提とした実装例。実リポジトリで別のフィールド名やモジュール方式なら契約を保って移植する。これを旧indexへ丸ごと貼る依頼ではない。

- 新規v2診断のindexで見せるMIRRORは`selection.mirror`。
- 保存する`mirror_snapshot`も同じ選択結果から作る。
- MY IDENTITY / CURRENT OBSERVATION / レポートのMIRROR見出しは、保存済みsnapshotを優先して一貫した人物を表示する。
- 全118名のスコアランキングは`selection.rankings`。ユーザーはランキングの表示方法を別検討としたため、今回、レポートの一致率表・順位UIを再設計しない。
- 同率時には表示MIRRORとスコアランキングの先頭が異なり得る。`rankings[0]`をMIRRORとみなす呼出箇所を必ず洗い出す。MIRROR表示と一致率ランキングの役割を混同しない。
- 選択根拠、同率数、適用ルールは可能ならsnapshotの既存JSON構造に互換性を保って記録する。未知のDBカラムを勝手に追加せず、RPCスキーマ・既存バリデーションを確認する。

生スコアランキングを属性で全体的に並べ替えたり、選択キャラを無条件で先頭へ動かして一致率順位を偽らない。全体順位のUI変更は今回の範囲外。

## 7. 保存・過去結果・権利の保持

新規v2結果のみ新しい座標と選択版で計算し、6種類の版情報とMIRROR snapshotを保存する。新規保存と画面表示が同じ人物を参照するようにする。client_session_idの冪等性、回答保存、既存認証、購入権を維持する。

旧版/v2旧座標の保存済み結果は当時のsnapshotと版を維持し、新座標で自動再計算しない。旧レポート閲覧権、CORE到達履歴、保存履歴を今回変更しない。旧versionが明示された結果へ新データを黙って適用しない。

旧v2のsnapshotが欠けたケースは、実際のresolverと保存内容を確認して復元方針を報告する。当時のDB/モデルを復元できないのにRC4へ差し替えて旧結果と呼ばない。

未保存の旧共有URLなど、回答と旧versionしかないケースも旧版を尊重する。新規共有URLで採用した座標版・選択版を識別できる仕組みも、既存のURL/保存契約を確認して保持する。版情報がない旧リンクを確実に復元できると主張せず、現行運用の扱いを調査して報告する。過去のキャラDBをresolverで参照する必要があるなら旧ファイルを残し、新版の読込経路と分ける。既存の最新版ファイルを置換するだけで旧URLの結果が変わる構成なら、その問題を解消する。

## 8. 実装後の検証・受入条件

パッケージ単体：

```sh
node verification/verify_handoff.cjs
```

用意した検証は203件の人工100問回答の20軸・選出人物・上位4名/生スコア、118名の自己再入力、12件の同率/境界/不変性テスト。参照実装では全件成功している。

実リポジトリでも少なくとも以下を確認する：

- 118名が欠損なく入り、JSON/JS/CSVの20軸と一致する。事実メタデータと確定canonical順を維持する。
- 設問・ユーザー採点・翻訳の既存テストが不変。既存の必要な回帰/E2E検証を通す。
- 203件のfixtureを実リポジトリの採点・MIRROR関数に通し、同じ20軸と選択人物になる。
- 丸め前同率：元素→国家→武器→固定番号。表示整数が同じでも生スコアが違えば高い方を選ぶ。
- ε境界と3候補の非推移性を確認。属性側の複数同率・平坦国家を確認する。
- 118名の本人プロフィール再入力で本人を選出する。
- 新規index表示→保存→マイページ→レポートMIRROR表示で同じ人物・同じ版。
- 同率選択キャラと生スコアランキング先頭が違う人工ケースでも、保存snapshotが選択キャラを保持する。
- 保存リトライの冪等性、未回答拒否、encode/decode、既購入権・旧レポート・旧v2 snapshot表示が壊れない。
- 既存の旧共有URL/旧version resolverを確認。旧結果がRC4へ自動変換されない。
- 同じ入力から常に同じ結果になる。抽選・実行時頻度補正がない。

fixtureの0〜100生スコアの数値比較は許容誤差1e-10pt。診断20軸と選出人物は完全一致。実装で差が出たら座標を再調整して合わせず、原因を調べる。

## 9. 検証結果の扱いと制限

新しい人工4万回答でRC4選出率0.635%〜1.0875%、平均100/118=0.8474576%、最多/最少1.71倍。114人が平均±0.2pt以内。これは実利用者の等確率を保証しない。一般6生成群では最少0.39%・最多1.49%、選出ゼロなし。平坦・領域偏重等の境界ケースではゼロ選出が残る。

同じ新しい4万回答で前回RC3の1回答1段階変更率11.7275%→RC4 11.815%。添付基準よりは不安定化が残る。元データからのMIRROR変更率65.2%。以前の結果を上書きしない理由でもある。

通常6万件では完全同率0件。同率処理そのものが今回の均等化を生んだわけではない。確定座標が均等化の主体で、属性同率処理は補助。

数値保護は緩和済み。最終実測の最大軸移動15、最大キャラRMSE7.159、最小領域形状相関0.9169。元の最高軸集合は全118人の全3領域で最高の位置に残る。最低軸が変わったクレーP（C→N）、ロサリアV（CO→TR）、クロリンデV（HE→PO）はユーザー確定版に含めて採用する。これを理由にClaude Code側で座標を勝手に戻さない。

すべての数値を物語根拠から再採点したわけではない。過去の再監査要約・出典一覧はreferenceへ同梱。source/evidenceラベルを新しい心理測定の妥当性証明としてUIに出さない。再シミュレーションや再最適化は今回の実装依頼に含めない。
