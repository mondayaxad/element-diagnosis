## 2. 設計書との照合結果（直したこと・確かめたこと）

1. **正本の形**：設計書は `ELEMENT_PROTOTYPES_V2.values[e][a]` と書いているが、実際は `ELEMENT_PROTOTYPES_V2[e][a]`（`.values` なし）。武器種・国家も同じ。実装は実物に合わせた
2. **計算式は本家と完全一致**：pSim・sSim（RMSE）、vSim（平均中心化コサイン、零ベクトルは 0.5）、総合参照値（0.40/0.30/0.30）を、本家 `js/eti_v2_engine.js` の `computeMirrorV2` と 280件で突き合わせ、すべて一致（浮動小数点まで同じ）
3. **軸の並び**は本家 `ETI_V2_META` と同じ（性格 O,C,E,A,N／行動 AGY,REL,ROL,REF,AUT／価値観 SD,ST,HE,AC,PO,SE,CO,TR,BE,UN）
4. **注記**（「この図は、選んだ元素・武器種・国家の代表モデルと…一致率ではありません。」）はレポート冒頭に1回置いた
5. **章の順**：人物名 → PERSONA → **RESONANCE** → STYLE → VALUES → SYMBOLS → JOURNEY（「購入直後は MIRROR との共鳴の要旨を最初に」に合わせて RESONANCE を2番目にした。変更可）
6. **VALUES の図**は元の値（0〜100）をそのまま描き、本文の共通点・相違点は平均中心化した相対優先度で選ぶ（設計書どおり）。そのため「図では離れて見えるのに本文では共通点」という見え方が起こりうる。気になるなら図も中心化値で描く案あり
7. **SYMBOLS** は元素7本の図だけ（選んだ元素は距離0で先頭・最長。図の下の文で「ほかの元素を個別に測定した結果ではない」と注記）。武器種・国家の順位は計算しているが、文章用に保持するだけで本文にはまだ使っていない

## 3. 280件の監査（詳しくは `audit_280.md`）

- 3側面の差が 0.05 未満（偏りなし）：**31件**
- 「近い側面」（偏りなしを含め最も近い側面）：価値観 107・行動 104・性格 69 — 極端な偏りはない
- 共通点・相違点に挙がる軸は 20軸に分散（最多でも 31件）
- 割り当てられた人物が、同じ代表モデルで66名を本家の総合参照値で並べた時の順位：**1位 132件・2〜3位 63件・4〜10位 75件・11位以下 10件**
  → 半数以上で「いちばん似ているから現れた」は事実ではない。設計書の禁止（「類似度が一番高いから」と書かない）の裏付け

**決めてほしいしきい値（暫定値で実装済み）**
- `FLAT_DOMAIN = 0.05`：3側面の差がこれ未満なら「大きな偏りはありません」
- `SMALL_AXIS_DIFF = 10`：相違点の軸の差（0〜100、価値観は中心化後）がこれ以下なら、違いを誇張しない文に切り替える（STYLE・VALUES・RESONANCE）

## 5. 購入・保存・再閲覧（C-3 の計画。今回は作っていない）

- **DB**（草案 SQL）：`resonance_orders`（金額 500 固定・回答の内部キー・サーバーが引き直した人物）、`resonance_reports`（スナップショット JSONB とその sha256。注文ごとに1件）、`resonance_access_tokens`（リンクの乱数はハッシュだけ）、`resonance_webhook_events`（重複配送の冪等化）。公開ロールは全拒否、サーバー（service_role）だけ
  - 本家の `stripe_webhook_events` は livemode=false の制約と `complete_orders` への外部キーがあるため流用しない
- **流れ**：購入ボタン → サーバーが回答を検証し固定割当表から人物を引き直して注文を作成 → サーバー発行の Stripe Checkout（metadata は注文 ID だけ）→ 署名検証済み webhook で金額・商品・環境を再確認 → スナップショットを1度だけ作成・保存 → 閲覧リンクを発行
- **再閲覧**：本家の方式（`#t=` の断片 → 交換 API → httpOnly Cookie、DB は `link_token_hash` だけ。`api/complete-status.js` 参照）にそろえる。保存済みスナップショットだけを表示し、計算し直さない（`renderReportHtml` は保存値だけで描く。試験済み）
- 販売スイッチ・Stripe の Price/Product ID・金額はサーバーの定数／環境変数だけ。Preview の試験が本番に書き込まない既存のガードに従う
- 法務（特商法・最終確認画面・返金条件・利用規約・プライバシー・キャラクター名の扱い）は設計書§6 のとおり、実際の事業者情報と別途の確認が必要。Claude は文面を作っていない
