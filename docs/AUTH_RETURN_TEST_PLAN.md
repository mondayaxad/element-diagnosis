# 認証復帰・保存の実機確認手順（Preview）

- 対象：release-c-preview の Vercel Preview URL（Supabase はテストプロジェクト `akivoobkqcnqvdumxtmg`）
- 目的：ブラウザごとに、次の3点を確認します。
  1. 未ログインで「保存」を押す → Googleでログイン → `/mypage.html` に戻る → 記録が1件だけ保存される
  2. 同じ結果をもう一度保存しても増えない（重複防止を適用した後）
  3. X アプリ内ブラウザで何が起きるか
- **注意**：このファイルに書かれた「予測」は、実機で確認するまで仕様として扱わないでください。

## 0. 準備
- テスト用の Google アカウントを1つ用意します。確認のたびに Supabase の Preview でそのアカウントの記録件数を確認し、記録しておきます（SELECTのみ）。
- 共通の確認SQL（読み取り専用）：

```sql
select s.id, s.completed_at, s.client_session_id, s.diagnosis_version, a.encoded_answers
from diagnosis_sessions s join diagnosis_answers a on a.session_id = s.id
where s.user_id = '<テストユーザーのid>' order by s.completed_at desc limit 10;
```

- 毎回、次のことを記録します。
  - 端末とOSの版
  - Xアプリの版
  - 開いたブラウザ（アプリ内 / Safari / Chrome）
  - 認証後に着いたページのURL
  - 画面の表示
  - SQL で見た件数の変化

## 1. ケース一覧

| # | 環境 | 手順 | 確認すること | 予測（未確認） |
|---|---|---|---|---|

| S2 | iOS Safari | S1の直後に、同じ結果URL（マイページの「この結果をもう一度見る」）を開く | 重複防止を適用する前は「保存」を押すと+1になる（現状の問題）。適用後は「保存済み」と表示され、件数は変わらない | 現状は+1 |
| C1 | Android Chrome | S1と同じ | S1と同じ | 成功する |
| C2 | iOS Chrome | S1と同じ | S1と同じ | 成功する |
| X1 | iOS Xアプリ | 自分のポストなどに Preview URL を置き、Xアプリ内で開く → 回答 → 保存 → Google | 次のどれになるか記録する：(a) アプリ内でそのままログインできる (b) Google のエラー（`disallowed_useragent` など）(c) Safari など外部ブラウザへ移る | (b) の可能性が高い |

| O1 | 共通 | 「外部ブラウザで開く」メニュー（Xの「…」→ ブラウザで開く）で開き直してから保存 | S1 / C1 と同じ結果になるか | 成功する（利用者向けの回避策の候補） |

## 2. 失敗したときに記録すること
- 画面のスクリーンショット（エラー画面、戻った先、ボタンの状態）
- 戻った先のURL（クエリと `#` 以降も含めて。ただしアクセストークンが含まれる場合は伏せる）
- Safari / Chrome の開発者ツールが使える場合は、localStorage の `pendingDiagnosis_v2` が残っているかと、コンソールのエラー

## 3. 判定
- X1〜X4 のどれかで「保存されない」「行き止まり」が再現したら、設計書 §7 の候補B（サーバー側 pending token）の実装を検討します。
- (b) の場合は候補Bでも解決できません。Google の制限なので、外部ブラウザへの案内（候補A）が必要です。
- どのケースも、**確認できていないものは「未確認」のまま報告します。**
