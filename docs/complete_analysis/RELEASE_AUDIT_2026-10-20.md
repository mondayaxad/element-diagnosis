# リリース前の監査（2026-10-20・release-c-preview）

5つの領域（購入の流れ・マイページとログイン・レポートの画面・結果ページとサンプル・サーバー/DB/公開設定）を、
コードの読み込み・Playwright・PG17 の試験で監査し、見つかったものを直した。全試験（566件）と公開ビルドの検証を通している。

## 直したもの

| 重さ | 内容 | 直し方 |
| --- | --- | --- |
| 致命 | マイページの「結果を見る」から開いた結果（`/?dv=ETI-2.0&code=`）では、購入の準備ができず買えなかった | 結果のリンクに記録 ID（`#rec=`）を付け、ログイン中の本人の記録を購入の対象にする。共有・ブックマークの `?code=` は、押した時にその結果の固有リンクを作る |
| 重大 | 同じタブで別の固有リンクを開いた後、マイページから開いた解析レポートの最下部・アドレスバーが、前の固有リンク（別の記録）を使っていた（別の記録で購入・登録しうる） | 入口のページが「開いた閲覧 URL」と組で控え、レポートの画面は自分の URL と一致した時だけ使う。マイページから開く時は控えを消す |
| 重大 | 完全解析の画面の「マイページに登録する」・期限切れの開き直しが、前の固有リンクを使いうる | 閲覧トークンを入口へ渡し、一致した固有リンクだけを使う。マイページから開いた完全解析には登録の欄を出さない |
| 重大 | 支払いの反映と同時に固有リンクを開くと「このリンクは無効です」と出ることがあった | 反映の直後に作られた納品を探し直す |
| 重大 | サンプルが、端末に残った別の人の診断結果（localStorage）で申込を出しうる | 端末に残った結果は使わない。同じタブの記録だけ（確かめられた後に保存・期限は受け取った時刻から） |
| 重大 | マイページで買ったレポートがマイページに出ない（買い直しを招く） | マイページから申し込んだ時は、支払いの後にマイページへ戻り、そのアカウントに登録する |
| 重大 | ログイン（Google・X）直後の描き直しで、登録の結果・確かめの欄が消えることがあった | 結果を描き直しの間も保つ。再試行はその場で行う。古い印で別の予定を登録しない |
| 重大 | supabase-js を版を固定せずに読み込んでいた（ログインの情報に触れる） | 2.117.3 に固定し、SRI（integrity）を付ける。html2canvas・jsPDF にも SRI |
| 中 | 全ページのセキュリティの見出し（埋め込み禁止・MIME・Referer）、/report・/purchase-complete・/mypage の noindex など | vercel.json に追加（API は除く） |
| 中 | 解析レポートのサンプルの GA4 が、Preview からも本番の計測に送り、URL を消毒していなかった | 共通の js/ga.js に統一 |
| 中 | 決済画面を作りすぎる（購入対象トークンがあれば無制限） | 同じ記録で1時間に20件まで（同じ購入操作の再送は止めない） |
| 中 | 二度押し・Enter の連打で目標の画面が重なる／注文が2つできる | 申込は同時に1つ・目標の画面は1つ・Escape はどこでも閉じる |
| 中 | 再送時に決済画面の期限が変わり、Stripe の再送が失敗しうる／別の秘密値になりうる | 期限は注文の作成時刻から・秘密値は注文のもの |
| 中 | 確認中・停止のレポートに買い直しのボタン（二重のお支払い） | 返金の後だけ買い直せる |
| 小 | 入口のページの状態の取り違え・待ち時間の上限後の案内・320px の横はみ出し（サンプル）・残っていた注釈 など | 個別に修正 |

## Production の前に必要なもの（Preview では対応不要）

1. **本番の DB の移行は別に書く**：complete_13 は Preview 専用（`stripe_mode = 'test'` を固定・Preview の確認つき）。
   本番で同じものを当てると、本番の支払い（live）が `livemode_mismatch` で失敗扱いになる。本番用の移行は、本番に進む時に作る。
2. 運営者の「リンクの再発行」（SQL Editor だけ）は、停止したリンクも有効に戻す。悪用で停止したものを再発行しない（手順書に記載）。
3. 固有リンクの秘密値は Stripe（戻り先・請求書）にも残る（運営者の判断で受け入れ済み）。Stripe の管理画面を見られる人はレポートを開ける。
