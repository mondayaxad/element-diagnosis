## 2. 作ったもの
| 範囲 | 内容 |
|---|---|
| トップの一覧（`index.html`） | 7元素を紋章（`assets/emblems/2026-autumn/record`）・元素名（明朝）・元素色で見分ける。開くと「タイプ名・武器種・コード」の5行。開ける元素は一度に1つ |
| 一覧の状態を戻す | 解説の「全35タイプ一覧に戻る」は `/#types-<元素>`（開いてその位置へ）。ブラウザの「戻る」でも、開いていた元素が開く（URL の `#types-<元素>` と sessionStorage） |
| 解説ページ（`scripts/build-type-pages.mjs`） | ヒーロー（炎 × 片手剣／殉愛者／タイプコード／タイプ別レポートへ進むボタン）→ タイプの核の引用 → 導入 → 紋章の図 → 章「元素の気質」「武器種の関わり方」（大見出し・本文・引用）→ 章「強みと、つまずきやすいところ」→ 同じ元素のほかのタイプ・一覧へ戻る |
| 解説の中身 | 結果ページ（`index.html`）と同じ文章資産から組み立てる：引用・強み・つまずき＝タイプ固有の説明（`TYPE_DESC` の1〜3文目）、章の本文＝`ELEMENT_DESC`・`WEAPON_DESC`、章の大見出し＝元素の軸（`ELEMENTS.axis`）・武器種の原理（`WEAPONS.principle`）。新しい性格描写は書き足していない |
| 標準プロフィール | ページには数値を出さない（代表値が決まるまで表示しない）。レポートの「ご利用いただける内容」に「標準プロフィールの読み方」として含める |
| タイプ別レポート（Preview 専用） | 「『殉愛者』の全編を解放」「今すぐアクセス　¥1,000（税込）」。押すと購入確認（対象タイプ・価格・読める内容）。デモなので購入へは進めない |

- title・description・canonical・OGP・JSON-LD は、既存ページから文字どおり取り出したもの（`scripts/type-pages-data.json`）を使う。
- 武器種の解説は、旧い静的ページの文（「援助者・堅実家の性質」）ではなく、結果ページの最新の文（「支え合いと信頼を重視する傾向」）にそろえた。
- ボタンはサイトの見出しと同じ明朝・字間・丸みのある形にした。
- ページの目的はタイプ別レポートの購入。type-v2 のページからは無料診断のボタン（上部の `data-type-cta="top"`・末尾の `bottom`）を外した。上部は「<タイプ名>のタイプ別レポートを読む →」（レポートの欄へ移る。Preview 専用）。邪眼診断への関連リンク（`related`）は残す。
- 本番に出すと、type-v2 のページでは GA4 の `type_diagnosis_cta_click` の top・bottom が発生しなくなる（related は残る）。レポートの計測は販売実装時に提案する。
- 標準プロフィールとレポートの欄は `hidden` で書き出し、本番ドメイン以外でだけ表示する（`js/type-detail.js`）。誤って main に入っても、本番には出ない。
- 炎のページで緑だったボタン・引用枠は、元素色に置き換えた（3ページとも）。

## 3. 代表値の調査
| 候補 | 出どころ | 算出方法 | 尺度 | タイプ別か |
|---|---|---|---|---|
| A. 元素の設計上の代表値（**いま Preview に表示**） | `js/eti_v2_prototypes.js` の `ELEMENT_PROTOTYPES_V2`（設計書§6.1）。診断の元素判定に使う値 | 設計値（受検者データではない） | 0〜100（受検者の Big Five 表示と同じ） | **元素ごと**（同じ元素の5タイプで同じ値） |
| B. 武器の設計上の代表値 | 同 `WEAPON_PROTOTYPES_V2`（§6.2） | 設計値 | 0〜100。軸は行動スタイル（主導性・関係調整・役割持続・媒介思考・自律距離）で Big Five ではない | 武器ごと |
| C. キャラクター設計値の平均 | `docs/eti_mirror_v21/ETI_CHAR_2_1_0.json`（118人。承認済み） | 同じ元素×武器種のキャラクターの Big Five の平均 | 0〜100 | タイプ別。ただし1タイプあたり1〜8人 |
| D. 受検者の平均 | 本番 DB の保存済みの結果（`v2_scores.personality`） | 未算出 | 0〜100 | タイプ別 |

- 受検者の Big Five 表示は `((平均 + 2) / 4) × 100`（-2〜+2 の回答の平均を0〜100に直した値）。A〜C も同じ0〜100で並べられる。
- 参考：C の値（炎×片手剣：ベネット・ドゥリンの2人で O63 C55 E50 A78 N55／氷×片手剣：6人で O62 C73 E36 A55 N56／雷×片手剣：3人で O60 C78 E50 A48 N45）。
- D は本番 DB の読み取りが必要なため、今回は行っていない（承認範囲外）。算出する場合は、タイプ別の人数（少ないタイプの扱い）と、保存した人だけの偏りを決める必要がある。
- モックの数値（66・73・68・58・62）は、どの候補とも一致しない仮の値。
- 推奨：タイプごとに違いを出すなら「A（元素の Big Five）＋ B（武器の行動スタイル）」の2つを並べる設計値の表示が、出どころを説明しやすい。受検者の平均（D）は、件数がそろった後で「実際の受検者の平均」と分けて表示する。

## 4. 全35タイプへ展開する時の変更範囲
- `node scripts/build-type-pages.mjs`（引数なし）で、残り32ページを同じテンプレートで書き出す。本文・SEO の head は元データのまま。
- 7タイプ（片手剣5つと PYCM など）にだけある導入文は、ある場合だけ表示する（ほかのタイプは導入文なし）。
- テスト：`tests/type_pages_v2.test.js` の「type-v2 のページ」の一覧を35件に更新する。
- 代表値の方針が決まったら、テンプレートの標準プロフィールの値の出どころと注記を差し替える。
- 販売開始時：Preview 専用の表示を外し、購入確認から決済（Stripe）・提供方法・GA4 イベントをつなぐ（別途承認）。
