# Claudeへの実装指示

このパッケージは、ユーザーが確認してから渡す実装仕様の確定候補です。サイトを実装する際は、data/とruntime.mjsを正本として使ってください。evidence/から別モデルを選んで混ぜないでください。

## まず確認

現行リポジトリのブランチ、HEAD、未コミット変更、作業対象のプレビュー・本番を確認。添付されていた古いindex.html、mypage.html、diagnosis-save.js、handoffには旧50問・エニアグラム・element-v1等が含まれるため、現行ETI v2として上書きしないでください。

このパッケージだけを根拠に本番DB変更・デプロイ・Stripe商品作成・販売開始を行う指示ではありません。まず独立した作業ブランチとプレビューで完成させ、差分と検証結果を提出してください。

## 実装順

1. 現行サイトの構成・保存・認証・共有・購入権限を確認する。
2. `/jagan/` のTOP・質問・完了画面をUI_SPEC.mdに沿って作る。
3. data/を使いruntime.mjsと同じ計算結果になるよう統合する。既存ETIの採点関数は改変しない。
4. 欠測、型の偏りなし、元素・型・人物の同率／近接の表示を実装する。
5. 既存の認証とマイページへ、邪眼結果の保存・再表示を追加する。
6. 公開要約、共有ページ、OGP、画像保存、X共有を実装する。publicSummaryの許可リストを守る。
7. レポート本文・サンプル・購入権限の土台を作る。価格は1,000円の1商品。sales_open=falseでは購入できない状態にする。
8. RELEASE_CHECKLIST.mdを実行し、差分・プレビューURL・検証結果・未解決事項を提出する。

## 大切な実装境界

- 人物はピエロとパンタローネを含む11名。目標各約9.09%。
- 人物類似度は、作品解釈から作った利用者側の回答参照パターンとの近さ。公式の人物心理得点として説明しない。
- 50問の原稿はQUESTIONS_50.md、データ正本はdata/items.json。設問IDと表示位置を混同しない。
- 1〜5の回答を使う。ETIの別の回答範囲を流用しない。nullは欠測で中間点に埋めない。
- 保存時はサーバーで認証・版・採点を検証。ブラウザが送る所有者・人物・購入済み情報を信用しない。
- 保存結果には版とスナップショットを残し、更新後も保存時の結果を再現する。
- 閲覧用の公開共有IDと、本人の保存結果・認証・購入権限を分ける。
- 本人以外のデータ閲覧・更新・削除を防ぐ。公開要約から有料レポートが読めないことを確認する。
- GA4に生回答・12スコア・非公開IDを送らない。
- 既存ETIの履歴、旧購入、共有経由の購入、認証復帰、マイページのランク構造を維持する。
- 背景・人物JPGなしで成立する赤黒いUIを初期構成とする。OGP生成待ちで結果表示を止めない。

## 参照実装の使い方

data/のitems、interpretation、characters、productをbundleとして渡し、computeDiagnosisを実行します。サーバーでも同じ版を使って再計算してください。設定のロード方法は現行プロジェクトへ合わせてください。

runtime.mjsのpublicReleaseVerified=falseは、この資料で本番実機確認をしていないことを示します。このフラグを変えるだけで公開可能と判断しないでください。公開時には実装・検証の記録とともに結果のstage・版を管理してください。

## 価格・決済

価格は1,000円・買い切り1商品で確定済みです。追加プランや月額化は行わないでください。既存ETIの価格IDは流用せず、邪眼用の商品・結果・本人に紐づく購入権限と決済復帰を確認してから販売します。価格確定だけでsales_openをtrueにしないでください。

## 完了報告

ユーザーがそのまま判断できるよう、変更点、影響する既存機能、プレビューURL、実行した検査、未確認事項、適用予定DB変更と撤回方法をまとめてください。計算テストだけで、保存・RLS・決済・本番公開が成功したとは報告しないでください。
