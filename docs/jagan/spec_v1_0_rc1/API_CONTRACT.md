# 保存・共有の契約案

以下の名前は意味を固定するための案。現行本番リポジトリを確認し、ルーティング・DB名に合わせて実装する。ここから推測して本番DBへDDLを適用しない。

## 保存

想定：認証済みPOST `/api/jagan/save`。

入力はresultId、itemSetVersion、answers。所有者はサーバー側の認証から決める。クライアントが送ったuser_id・購入済みフラグ・人物名・一致率を採用しない。

サーバーは固定された同じ版で再計算する。未知の設問ID、不正な回答、存在しない版は拒否する。過去版をサポートするなら、その版のデータを保持し、最新の係数で無断に再採点しない。

同じ所有者・同じresultIdの保存再試行は重複させない。別の所有者のresultIdに上書きできない。保存成功後は保存時のスナップショットと版を再表示する。

保存対象：生回答、欠測、12領域の平均・換算点・回答数、元素・型・人物の全順位、代表、同率・近接候補、判定保留理由、各版。保存は購入・公開共有を意味しない。

未ログインなら今回の結果を一時保持→認証→保存へ復帰。pendingキーをETIと混ぜない。保持期間と破棄は、現行の検証済み運用とそろえて確定する。

## 公開共有

共有は本人の操作で作成する。公開する値はpublicSummaryの許可リストだけ。保存スナップショット全体を返すAPIと共用しない。

共有URLの案は `https://同一サイト/jagan/s/公開ID`。公開IDは非公開結果ID・認証トークン・購入権限に使わない。URLに生回答の可逆コードや12スコアを入れない。

想定POST `/api/jagan/share` は、認証済みなら本人の保存結果から、未ログインなら送られた回答と版からサーバー側で再計算し、公開要約を作る。本人の操作なしに公開しない。匿名共有の取消手段は、現行の仕組みに合わせた非公開の取消用情報等を設計し、公開IDだけで他者が削除できるようにしない。

GETの共有ページ・OGPには公開要約だけを渡す。生回答、12項目、所有者、購入権限、非公開結果IDは返さない。削除済み・期限切れ・無効な共有IDには説明と診断入口を出す。

共有URLとそのOGPは同じモデル版の結果を表示する。公開要約を最新係数で無断更新しない。共有ページから有料レポートへアクセスするには、別に本人の購入権限が必要。

## マイページ

既存マイページの認証・保存の流れに合わせ、邪眼履歴を追加する。元素診断の既存履歴・旧購入・現在の購入ランクを保持する。jaganの購入権限をETIから自動付与しない。

本人以外の読み取り・書き換え・削除を拒否する。本人の削除、共有取消、保持期間について現行案内との整合を確認する。

## 購入

data/product.jsonはsales_open=false、price=1000、billing=one_time。1,000円の1商品で確定済み。商品・決済の設定と確認が完了するまで購入を開始しない。クライアントの設定表示だけで販売可能と判定せず、サーバーの設定と対象商品の権限を確認する。

既存ETIのStripe商品ID・価格IDを邪眼用として流用しない。新たな決済実装を行う段階でStripeの現行実装・公式資料を確認する。このパッケージには本番決済コードや商品作成は含まれない。

## 計測

開始・完了・保存・共有操作・画像保存・レポートCTAなどの操作イベントを中心に、送信項目を許可リストで定める。生回答・12スコア・非公開ID・認証情報をGA4へ送らない。ページURL・参照元の自動送信も確認する。
