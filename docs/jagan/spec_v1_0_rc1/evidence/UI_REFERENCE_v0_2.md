# 邪眼診断｜TOP・完了ページ・共有設計 v0.2

作成日：2026年11月2日
状態：画面・共有仕様案。実装・公開・価格確定は未実施。
関連：JAGAN_measurement_design_v0_1.md（測定設計は継続）。本書は画面・共有の追加仕様であり、50問の設問原稿や元素・タイプの判定確定を意味しない。

## 1. 今回の指定と設計上の仮置き

ユーザー指定：同一サイト内の別ページで独立したTOPとして見せる。元素診断の構成を引き継ぎ、赤黒い夜、筆記体の英語、赤系ボタンを採用する。完了ページには深淵、元素×タイプ、解説2段、ファトゥス、邪眼元素一覧、保存・画像保存・Xシェア、レポート導線、末尾の価格を配置する。

仮置き：「〇〇×〇〇」は邪眼元素×邪眼タイプ。「風 水 雷」は邪眼元素の上位3候補で、ユーザー自身が選び直すボタンではない。順位・候補数は判定設計と整合させる。スカラマシュと87%は表示例であり、確定した採点結果ではない。

## 2. URLと既存診断との境界

- 候補URL：同一オリジンの `/jagan/`。実際のルート構成は現行リポジトリを確認して決める。
- TOP→50問→完了画面の流れを邪眼診断内で完結させる。元素診断の事前受検は不要。
- 戻るリンクは「元素診断へ」。邪眼ページにも自分自身のタイトル・説明・共有メタ情報を用意する。
- 既存ETI v2の設問、採点、共有パラメータ、保存履歴、購入権限は変更しない。
- 添付ファイルは画面構成の参考とし、そのまま現行本番ソースと認定しない。添付のindexには旧50問・Enneagram表記があり、v2の100問構成と異なるため。

英語は装飾として使い、日本語の診断名と主要操作は読みやすさを優先する。

## 5. 完了ページの表示順

### ① あなたの深淵

小見出し「あなたの深淵」。中央に大きく「風 × 〇〇」を表示する。〇〇には判定済みの邪眼タイプ名を入れる。

その下に短い文章を2段置く。
- 第1段：回答に表れた欲求・葛藤・感情の扱い方を伝える。
- 第2段：その特徴が現れやすい場面や、内省のための問いを伝える。

無意識の本性・原因・疾患を断定しない。全項目が低い、拮抗する、欠測が多い場合にも、強い闇や葛藤を捏造しない。判定できない項目には「判定保留」を使う。

### ② 最も近しいファトゥス

表示例：「最も近しいファトゥス：スカラマシュ（87%一致）」。
名称と一致率の直下に共通点を短く記載し、「一致率について」から説明を開ける構成とする。
キャラクター画像はなくても成立させる。

### ③ あなたの渇望する邪眼

上位3元素を横並びで表示する。例：風／水／雷。1位を最も大きくし、2位・3位は補助として表示する。スマートフォンでも順番が明確に伝わるよう、必要に応じて「1」「2」「3」を添える。

心理学的には元素への欲求そのものを測っていない。「あなたの渇望する邪眼」は創作上の見出しで、実際には回答プロフィールから導いた象徴的な候補であることを方法説明に記す。上位候補間の近さを客観的な差と断定しない。

### ④ 保存・共有

順序を「マイページ保存 → 画像保存 → Xシェア」とする。スマートフォンでは3つが読みやすい幅になるよう配置し、足りなければ縦並びにする。

- マイページ保存：元素診断と同じ保存の流れを使い、今回の邪眼診断結果を本人のマイページに保存する。保存後はマイページから邪眼の結果を開き直せる。本人の非公開記録として保存し、未ログインの場合も認証後にこの結果を保存できる導線にして、回答を失わせない。
- 保存する内容：邪眼元素・邪眼タイプ・ファトゥス・一致率・上位元素・結果解説に加え、レポートに必要な生回答・12項目の得点・各判定バージョンを保持する。表示結果は保存時の版で再現し、後日のロジック更新で無断に変えない。
- 既存マイページ内に邪眼診断の保存結果を表示する。元素診断結果は引き続き保持し、邪眼の結果で上書きしない。保存操作で公開共有やレポート購入が自動的に行われることはない。履歴件数・再受検時の扱い等は現行の保存仕様を確認して合わせる。
- 画像保存：結果の要約画像をユーザー操作時に生成する。生成中・失敗・再試行を表示し、他の操作を止めない。
- Xシェア：共有対象の要約を確認できるようにし、ユーザーが投稿画面で確定する。自動投稿はしない。

### ⑤ レポートへの導線

導入コピー案：
「ここで見えているのは、あなたの深淵の一部分に過ぎません。」
「願いが満たされるとき、揺らぐとき。そして、感情との向き合い方。その奥にある輪郭を、12の項目から読み解きます。」

販売範囲案：

| 紹介順 | レポート内容 |
|---|---|
| 1 | 自律性・有能感・関係性それぞれの充足と阻害：6スコア |
| 2 | 捉え直し・表出抑制：2スコア |
| 3 | 感情理解・感情受容・衝動調整・行動維持の困難：4スコア |
| 4 | 邪眼元素・タイプの解説、近しいファトゥスとの共通点と相違点 |

「レポートを読む」等の案内CTAは内容紹介へ導く。内容紹介→サンプル→末尾の価格・購入ボタン、の順にし、価格を見る前に決済へ移動しない。価格は未決定のため、設計上は「¥［価格未定］／買い切り」の位置だけ定義する。通貨、税込等の表示、購入条件は実販売時に確定する。元素診断の既存価格を流用しない。
販売準備ができるまでは購入ボタンを表示せず「レポート準備中」とする。

## 6. Xシェア文

テンプレート：

```text
邪眼診断をやってみました。
私の結果は、【{邪眼元素}×{邪眼タイプ}】

最も近しいファトゥス：{キャラクター名}（{一致率}%一致）

{共有URL}
#邪眼診断 #原神
```

一致率を算出できないときは括弧内を省略する。キャラクター自体を判定できないときも、無関係な候補で穴埋めしない。共有ボタンの近くで、要約結果と一致率が公開されることを分かるようにする。12スコア・生回答・購入権限・認証情報は共有文やURLに含めない。

## 7. 一致率の位置づけ：v0.1からの変更

v0.1は初期版の百分率を見送る案だったが、今回の指定により「%一致」を表示候補に追加する。科学的な人物一致確率ではなく、独自プロフィール比較の類似度指標として扱う。

- 12領域のうち、キャラクター側で根拠を持てる側面だけを比較に使う。
- 公式描写、設計者の解釈、参照時期、根拠の確かさをプロフィールで分けて記録する。
- 共通の比較項目集合と最低限の根拠量を先に定める。少数項目だけの比較と、多数項目の比較をそのまま順位付けしない。
- 不明な特性は中間点で補わず、比較可否を判定する。
- 計算法・重み・採点版は別途設計し、表示映えを目的に87%等へ引き上げない。
- 表示は整数。同点時の規則、全候補との距離が大きい場合、根拠不足の場合を定義してから公開する。
- 短い説明：「回答とキャラクターの描写を独自の基準で比較した類似度です。科学的な人物一致確率ではありません。」

ファトゥスの対象範囲、過去・現在のどの時点を比較するか、名称の扱いは未確定。スカラマシュを例示したことだけで、全候補のプロフィール設計が済んだとは扱わない。

## 8. OGPと画像の初期方針

OGPは既存の共有中継ページ＋結果カードの構成を参考に、赤黒版を作る。共有カードに入れるのは診断名、元素×タイプ、最も近しいファトゥス、一致率、小さなブランド表記。長い解説、12スコア、価格は入れない。

参考寸法は既存OGPを踏襲する方針。背景は黒と紅のグラデーション、文字、細い枠・光で構成する。背景JPG・キャラクターJPGは初期版では省略する提案。OGP画像そのものを廃止する意味ではない。

| 種類 | 生成・取得のタイミング | 結果ページとの関係 |
|---|---|---|
| TOP／完了ページの背景 | CSSで描画する初期案 | JPG取得の前提を置かない |
| 共有OGP | 共有URLに対応する画像として提供 | 結果表示時に生成完了を待たせない |
| 画像保存 | ユーザーがボタンを押したとき | 操作した本人にだけ生成中を表示 |

添付のog-image.mjsには外部フォントの取得処理がある。画像を省略しても生成時間がゼロになるとは限らない。現行実装を確認のうえ、フォントの同梱・再利用、結果別画像のキャッシュ、静的な共通OGPへのフォールバックを検討する。効果は未計測。
JPGを加えたときの遅延はファイルサイズ・読み込み方・配信状況によるため、現時点で秒数や改善量を断定しない。まず画像なしで基準を測り、必要なら画像ありと比較する。

## 9. 共有URLと非公開データ

邪眼専用の共有経路・データ形式を用意し、既存ETI共有コードのビット構成を流用・変更しない。公開用の要約と、本人向けの保存済み結果を分ける。
共有IDは保存・購入権限の代わりにしない。共有リンクから詳細な心理スコアや非公開レポートへアクセスさせない。共有をしなくてもマイページ保存は可能とする。
共有リンクは診断開始ページだけでなく、その共有要約に着地させる。無効・期限切れ・削除済みの場合は説明と再診断への導線を出す。OGPと着地画面で結果の版を一致させる。

## 10. 実装時の確認事項

- 同一の結果から完了画面・X文・OGP・保存画像が同じ元素、タイプ、人物名、一致率を表示する。
- 長いタイプ名・人物名、小さい画面、欠測・同点・判定保留でも崩れない。
- 保存後の認証復帰、画像生成失敗、共有取消、共有URLの再訪を確認する。
- 結果表示とOGP生成の待ち時間を分けて計測する。
- 既存ETIの購入・履歴・共有導線が変わっていないことを確認する。
- 価格未確定・販売未準備の状態で決済を開始できないことを確認する。
